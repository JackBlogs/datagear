### 1.3 核心编码范式

**(1) SFC 一律使用 `<script setup lang="ts">`**，纯 Composition API，不用 Options API、不写 `export default`：

```vue
<script setup lang="ts">
import { ref, computed, onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { useI18n } from 'vue-i18n'
import { userPagingQueryData, deleteUsers, type User } from '@/api/user'
import { useOperationMessage } from '@/composables/useOperationMessage'

const router = useRouter()
const { t } = useI18n()
const { success, fail } = useOperationMessage()

const items = ref<User[]>([])
const total = ref(0)
const loading = ref(false)
const page = ref(0)
const pageSize = ref(10)

async function load() {
  loading.value = true
  try {
    const data = await userPagingQueryData({ page: page.value, pageSize: pageSize.value })
    items.value = data.items
    total.value = data.total
  } catch (e) {
    fail((e as Error).message || t('queryFail'))
  } finally {
    loading.value = false
  }
}
onMounted(load)
</script>
```

**(2) 路径别名 `@/` → `src/`**：`tsconfig.json` 的 `paths` 与 `vite.config.ts` 的 `resolve.alias` 双配。

**(3) TypeScript 严格模式**：`strict: true`、`noUnusedLocals`、`noUnusedParameters` 开启。
所有后端契约都有 `.ts` interface 对应（见 `types/index.ts` 及 `api/*.ts` 内的 `User`、`Role` 等）。
类型检查通过 `vue-tsc --noEmit`（`npm run typecheck`，`npm run build` 前自动执行）。

**(4) 请求层统一封装**（`src/api/request.ts`）：

```ts
import axios from 'axios'
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || ''

const request = axios.create({
  baseURL: API_BASE_URL,
  timeout: 60000,
  withCredentials: true,   // Session + Cookie 同源
})

// 请求拦截器：携带 X-Requested-With（沿用后端拦截器语义）
request.interceptors.request.use((config) => {
  config.headers = config.headers ?? {}
  config.headers['X-Requested-With'] = 'XMLHttpRequest'
  return config
})

// 响应拦截器：401 → 清 auth store + 跳登录（redirectUrl 回跳）
request.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error?.response?.status === 401) {
      import('@/stores/auth').then(({ useAuthStore }) => useAuthStore().clear())
      import('@/router').then(({ default: router }) => {
        const redirectUrl = encodeURIComponent(router.currentRoute.value.fullPath)
        router.push({ path: '/login', query: { redirectUrl } })
      })
    }
    return Promise.reject(error)
  },
)

// 解包统一响应体，type=FAIL 时抛错（由调用方/组合函数统一 Toast）
export function unwrap<T>(res: { data: OperationMessage<T> }): T {
  const body = res.data
  if (body && body.type === 'FAIL') throw new Error(body.message || body.code || '操作失败')
  return body?.data as T
}

export function httpGet<T>(url: string, config?) { return request.get<OperationMessage<T>>(url, config) }
export function httpPost<T>(url: string, data?, config?) { return request.post<OperationMessage<T>>(url, data, config) }
export default request
```

**(5) 三种 API 调用风格并存**：

| 风格 | 文件 | 适用场景 |
|---|---|---|
| 通用 CRUD | `api/crud.ts`：`moduleGet/moduleSave/moduleDelete(module, ...)` | 简单实体模块（无特殊业务逻辑） |
| 专用 API | `api/user.ts`、`api/role.ts` 等，每接口手写函数 + 手写返回类型 | 有特殊业务逻辑的模块 |
| 分页加载器 | `api/paging.ts`：`createPagingLoader(module)` | 生成 `(query) => POST /api/{module}/pagingQueryData` |

```ts
// api/crud.ts
export function moduleGet<T>(module: string, id: string): Promise<T> {
  return request.get<OperationMessage<T>>(`/api/${module}/get/${id}`).then((r) => unwrap(r)!)
}
export function moduleSave<T>(module: string, entity: T): Promise<T> {
  return request.post<OperationMessage<T>>(`/api/${module}/save`, entity).then((r) => unwrap(r)!)
}
export function moduleDelete(module: string, ids: string[]): Promise<void> {
  return request.post<OperationMessage>(`/api/${module}/delete`, ids).then(() => undefined)
}

// api/paging.ts
export function createPagingLoader(module: string) {
  return (query: PagingQuery): Promise<PagingData<EntityRecord>> =>
    request.post<OperationMessage<PagingData<EntityRecord>>>(`/api/${module}/pagingQueryData`, query).then(unwrap)
}
```

**(6) 列表/表单视图的固定骨架**：

- **列表页**（`views/*/XxxListView.vue`）：顶部搜索表单 + 操作按钮区 + PrimeVue `DataTable`
  懒加载（`:lazy`、`@page`、`@sort`、`v-model:selection`、`data-key="id"`）。
- **表单页**（`views/*/XxxFormView.vue`）：新增/编辑/查看三态共用同一组件，
  用 `isEdit`（`!!route.params.id`）与 `isReadonly`（`route.query.mode === 'view'`）两个计算属性
  控制字段显隐与只读；保存后 `success()` Toast + `router.push` 回列表。

**(7) 组合函数复用**（`composables/`）：

- `usePagingTable<T>`：封装「DataTable 懒加载 ↔ PagingData」。
- `useOperationMessage`：封装 PrimeVue `useToast` 的 `success` / `fail` 提示。
- `useConfirm` / `useSearchForm` / `useSteps`：确认框、搜索表单、步骤向导。

**(8) 路由与守卫**（`router/index.ts`）：

- `createWebHistory()` history 模式。
- 路由组件全部 `() => import(...)` 实现按需加载（路由级代码分割）。
- `meta` 携带 `title`（菜单名）、`public`（是否公开）、`keepAlive`（多标签缓存策略）。
- 全局守卫 `router.beforeEach`：首次非公开导航调 `GET /api/auth/me` 判定登录态，
  匿名跳 `/login?redirectUrl=...`。

**(9) 权限与菜单**：`stores/auth.ts` 拉取 `/api/auth/me` 后，
把 `modulePermissions` 写入 `stores/permissions.ts`；`isReadonlyAction`（匿名只读）与
各模块 `visible/accessor/operator` 用于前端按钮显隐与菜单渲染。

### 1.4 与后端对齐的契约类型（`types/index.ts`）

```ts
export interface OperationMessage<T = unknown> {
  type: MessageType            // 'SUCCESS' | 'FAIL'
  code: string                 // i18n 消息码
  message: string              // 已解析文案
  detail?: string | null
  throwableDetail?: boolean
  data?: T
  success?: boolean            // isSuccess() 序列化字段
  fail?: boolean               // isFail() 序列化字段
}

export interface PagingData<T> { total: number; items: T[]; pages: number; page: number; pageSize: number }
export interface PagingQuery { page: number; pageSize: number; keyword?: string; orders?: Order[]; [key: string]: unknown }
export interface Order { name: string; type: 'ASC' | 'DESC' }
export interface ModulePermissions { dtbsSourcePermission; analysisProjectPermission; dataSetPermission; chartPermission; dashboardPermission }
export interface AuthMe { user: UserInfo; roles: string[]; anonymous: boolean; readonlyAction: boolean; modulePermissions: ModulePermissions }
```

### 2.3 分层架构与调用链（以「角色 Role」为最小范例）

**① Controller（`datagear-web/controller`）**

新前端走 `/api` 前缀的 `XxxApiController`，旧前端走 `XxxController`，二者双轨并存。

```java
@Controller
@RequestMapping("/api/role")
public class RoleApiController extends AbstractEntityApiController<Role> {
    @Autowired private RoleService roleService;

    @Override protected EntityService<String, Role> getEntityService() { return roleService; }
    @Override protected String getModuleName() { return "role"; }

    @Override protected List<Map<String, Object>> buildMetaColumns(HttpServletRequest request) {
        List<Map<String, Object>> c = new ArrayList<>();
        c.add(column("id", "ID", true));
        c.add(column("name", "名称", true));
        return c;
    }

    @Override protected void checkSaveEntity(HttpServletRequest request, Role entity) {
        if (isBlank(entity.getName())) throw new IllegalInputException();
    }

    @RequestMapping(value = "/delete", produces = CONTENT_TYPE_JSON) @ResponseBody
    public ResponseEntity<OperationMessage> delete(HttpServletRequest request, @RequestBody String[] ids) {
        return deleteByIds(request, ids);
    }
}
```

基类 `AbstractEntityApiController<T>` 提供开箱即用的端点：

| 端点 | 方法 | 返回 |
|---|---|---|
| `/api/{module}/pagingQueryData` | POST | `OperationMessage<PagingData<T>>` |
| `/api/{module}/get/{id}` | GET | `OperationMessage<T>` |
| `/api/{module}/save` | POST | `OperationMessage<T>`（按 `id` 判新增/更新） |
| `/api/{module}/delete` | POST | `OperationMessage`（子类实现） |
| `/api/{module}/meta` | GET | `OperationMessage<Map>`（列定义 + readonlyAction） |

基类预留的扩展钩子：`prepareSaveEntity` / `checkSaveEntity` / `persistEntity` / `getEntityForEdit` / `toFormResponseData`（清密码等）。

**② Service 接口 + 实现（`datagear-management/service`）**

```java
public interface RoleService extends EntityService<String, Role> { ... }

public class RoleServiceImpl extends AbstractMybatisEntityService<String, Role>
        implements RoleService, AuthorizationListenerAware {
    protected static final String SQL_NAMESPACE = Role.class.getName(); // SQL 命名空间 = 实体全限定名
    public RoleServiceImpl(SqlSessionFactory ssf, MbSqlDialect dialect) { super(ssf, dialect); }
    @Override protected String getSqlNamespace() { return SQL_NAMESPACE; }
}
```

`EntityService<ID, T>` 固定方法：`add / update / deleteById / deleteByIds / getById / query / pagingQuery`。
抽象基类 `AbstractMybatisService` 已实现「参数 Map 拼装 + SQL statement id 拼接 + 缓存读写 + 分页(count + query)」全套逻辑。

**③ 实体 Domain（`datagear-management/domain`）**

```java
public class Role extends AbstractStringIdEntity implements CloneableEntity, DescriptionEntity {
    private String name;          // 普通字段 = 表列
    private String description;
    private boolean enabled = true;
    @Override public Role clone() { Role e = new Role(); BeanUtils.copyProperties(this, e); return e; }
}
```

实体类名 + 字段名 → MyBatis `resultType` 自动映射（Mapper 里 `AS ${_iq_}xxx${_iq_}` 别名对齐驼峰字段）。

**④ MyBatis Mapper XML（`datagear-management/src/main/resources/org/datagear/management/mapper/`）**

必须实现的 statement id（约定俗成）：`insert / update / deleteById / getById / query / pagingQuery / pagingQueryCount`。
引用公共片段 `common.queryOrder`、`common.pagingQueryHead/Foot`（来自 `commonSqls.xml`），
列别名用 `${_iq_}name${_iq_}` 做跨库标识符引用（`_iq_` = identifier quote，由 `MbSqlDialect` 注入）。

**⑤ 数据库表（`datagear-management/.../ddl/datagear.sql`）**

```sql
CREATE TABLE DATAGEAR_ROLE (
    ROLE_ID VARCHAR(50) NOT NULL,
    ROLE_NAME VARCHAR(100) NOT NULL,
    ROLE_DESCRIPTION VARCHAR(200),
    ROLE_ENABLED VARCHAR(10) NOT NULL,
    ROLE_CREATE_TIME TIMESTAMP
);
ALTER TABLE DATAGEAR_ROLE ADD CONSTRAINT DG_PK_ROLE_ID PRIMARY KEY (ROLE_ID);
```

约定：表名 `DATAGEAR_*` 全大写、主键 `VARCHAR(50)` 字符串 ID（`IDUtil.randomIdOnTime20()` 生成 20 位时间戳随机串）、
布尔用 `VARCHAR` 存 `'true'/'false'`、时间用 `TIMESTAMP`。

**⑥ Service / Mapper 注册机制**

- Service 在 `datagear-web/config/CoreConfigSupport.java` 手动 `@Bean` 实例化并注入依赖：

```java
@Bean
public RoleService roleService() {
    RoleServiceImpl bean = new RoleServiceImpl(this.sqlSessionFactory(), this.mbSqlDialect());
    bean.setRoleSpec(this.roleSpec());
    return bean;
}
```

- Mapper 扫描在 `CoreConfigSupport#getSqlSessionMapperResources()` 使用
  `classpath*:org/datagear/management/mapper/*.xml` 一次性加载所有 XML，
  **新增模块无需改配置，只需把 XML 放进该目录**。

### 2.4 数据权限两条基类（新增模块必须二选一）

| 基类 | 适用 | 关键差异 |
|---|---|---|
| `AbstractEntityApiController<T>` | 无数据权限的全局实体（Role、User） | 分页 `pagingQuery(query)` |
| `AbstractDataPermissionApiController<T extends DataPermissionEntity & Entity>` | 有「创建人 + 授权表」数据隔离（数据源/项目/数据集/图表/看板） | 分页 `pagingQuery(user, query)`；新增自动 `inflateCreateUserAndTime` 写入 `CREATE_USER_ID`；删除带权限校验 |

对应 Service 基类分别为 `AbstractMybatisEntityService` 与 `AbstractMybatisDataPermissionEntityService`。
带权限的 Mapper 在 `queryView` 中 LEFT JOIN `DATAGEAR_AUTHORIZATION`，走 `commonDataPermissionSqls.xml` 的权限片段（参考 `AnalysisProjectMapper.xml`）。

### 2.5 内置角色与权限模型

- `ROLE_REGISTRY`（注册用户）、`ROLE_DATA_ADMIN`（数据管理员，可读写）、`ROLE_DATA_ANALYST`（数据分析员，只读）。
- 匿名用户只能只读（`readonlyAction = !hasDataManager(auth)`）。
- 资源级权限通过 `DATAGEAR_AUTHORIZATION` 表 + `AuthorizationService` 实现。

## 三、前后端请求响应体系

### 3.1 统一响应体 `OperationMessage<T>`

后端 `OperationMessage.java` ↔ 前端 `types/index.ts`：

```jsonc
{
  "type": "SUCCESS",          // SUCCESS | FAIL（Jackson 同时序列化 success/fail）
  "code": "operationSuccess", // i18n 消息码
  "message": "操作成功",       // 已解析文案（前端可直接展示）
  "detail": null,             // 可选，详细/堆栈
  "data": { ... }             // 业务数据（PagingData<T> / 实体 / null）
}
```

### 3.2 分页约定

- 请求：`PagingQuery { page, pageSize, keyword?, orders? }`，`page` 从 1 起。
- 响应：`PagingData<T> { total, items, pages, page, pageSize }`。
- 前端 PrimeVue DataTable 懒加载对接：`@page`（0 起，需 +1）、`@sort`（sortField/sortOrder → orders）。

### 3.3 认证与会话

- 登录：`POST /login/doLogin`（`application/x-www-form-urlencoded`，字段 `name/password/checkCode`）
  → 后端 302 到 `/login/success`（JSON）。
- 当前用户：`GET /api/auth/me` → `{ user, roles, anonymous, readonlyAction, modulePermissions }`。
- 退出：`POST /logout`（Spring Security 默认端点）。
- 注册：`POST /register/doRegister`；校验码：`GET /checkCode?m=LOGIN`。
- 会话：Session + Cookie 同源，`withCredentials: true` + `X-Requested-With: XMLHttpRequest`。

### 3.4 错误处理

- 业务失败：HTTP 200（或 400） + `OperationMessage.type=FAIL`；前端 `unwrap()` 抛错 → 组件 catch → `useOperationMessage().fail()` Toast。
- HTTP 401：响应拦截器清 auth store + 跳登录（携带 `redirectUrl` 回跳）。
- `ControllerAdvice` 按 content-type 分流：API 错误 JSON，页面 404/500 由前端路由兜底。

### 3.5 完整链路图

```
页面(views/*.vue) 组件(components/*.vue)
        │  调用 api/*.ts 的方法
        ▼
api/*.ts  (request.ts axios 实例，带 Cookie + X-Requested-With)
        │  HTTP 请求 /api/** 或旧 /xxx（JSON）
        ▼
Controller (AbstractController 子类)
        │  鉴权(Security) → 业务 Service
        ▼
Service (management/persistence/analysis/connection)
        │  MyBatis / JDBC / 文件系统
        ▼
数据库 / 文件 / 外部数据源
        │
        │  返回实体 / PagingData / 消息
        ▼
Controller 构造 OperationMessage<T> (JSON)
        │  HTTP 响应
        ▼
api/*.ts unwrap() 解包 → 组件 ref 更新 → 界面渲染
```

## 四、完整实现方法：新增功能模块端到端模板

以新增「字典管理 FooBar」模块为例，按顺序落地。以下步骤构成完整闭环：
**数据库 → 实体 → Service → Mapper → Controller → Bean 注册 → 前端 API → 前端视图 → 路由/菜单 → 验证**。

### 第 0 步：确认模块性质

- 是否要**数据权限**（谁能看/编辑）？→ 决定继承哪条基类（2.4 节）。
- 是否有**一对多 / 附件 / 加密字段 / 级联删除**等特殊逻辑？→ 决定是否像 `User` 那样重写 `save/delete/postProcessGet`。

### 第 1 步：数据库（`datagear.sql` 追加）

```sql
/*字典*/
CREATE TABLE DATAGEAR_FOO_BAR
(
    FB_ID VARCHAR(50) NOT NULL,
    FB_NAME VARCHAR(100) NOT NULL,
    FB_VALUE VARCHAR(200),
    FB_ENABLED VARCHAR(10) NOT NULL,
    FB_CREATE_USER_ID VARCHAR(50),
    FB_CREATE_TIME TIMESTAMP
);
ALTER TABLE DATAGEAR_FOO_BAR ADD CONSTRAINT DG_PK_FB_ID PRIMARY KEY (FB_ID);
```

### 第 2 步：实体（`datagear-management/domain/FooBar.java`）

```java
public class FooBar extends AbstractStringIdEntity implements CloneableEntity, CreateUserEntity {
    private static final long serialVersionUID = 1L;
    private String name;
    private String value;
    private boolean enabled = true;
    private User createUser;
    private Date createTime;
    // getter/setter + @Override clone()（BeanUtils.copyProperties）
}
```

> `CreateUserEntity` 要求实现 `getCreateUser()/getCreateTime()`，数据权限新增时自动注入创建人。

### 第 3 步：Service 接口 + 实现（`datagear-management/service`）

```java
public interface FooBarService extends DataPermissionEntityService<String, FooBar> { }

public class FooBarServiceImpl extends AbstractMybatisDataPermissionEntityService<String, FooBar>
        implements FooBarService {
    protected static final String SQL_NAMESPACE = FooBar.class.getName();
    public FooBarServiceImpl(SqlSessionFactory ssf, MbSqlDialect dialect) { super(ssf, dialect); }
```

### 第 4 步：Mapper XML（`mapper/FooBarMapper.xml`）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="org.datagear.management.domain.FooBar">

  <insert id="insert">
    INSERT INTO DATAGEAR_FOO_BAR (FB_ID, FB_NAME, FB_VALUE, FB_ENABLED, FB_CREATE_USER_ID, FB_CREATE_TIME)
    VALUES (#{entity.id}, #{entity.name}, #{entity.value}, #{entity.enabled, jdbcType=VARCHAR},
            #{entity.createUser.id}, #{entity.createTime})
  </insert>

  <update id="update">
    UPDATE DATAGEAR_FOO_BAR SET FB_NAME = #{entity.name}, FB_VALUE = #{entity.value},
        FB_ENABLED = #{entity.enabled, jdbcType=VARCHAR}
    WHERE FB_ID = #{entity.id}
  </update>

  <delete id="deleteById">
    DELETE FROM DATAGEAR_FOO_BAR WHERE FB_ID = #{id}
  </delete>

  <sql id="queryView">
    SELECT A.FB_ID AS ${_iq_}id${_iq_},
           A.FB_NAME AS ${_iq_}name${_iq_},
           A.FB_VALUE AS ${_iq_}value${_iq_},
           A.FB_ENABLED AS ${_iq_}enabled${_iq_},
           A.FB_CREATE_USER_ID AS ${_iq_}createUser.id${_iq_},
           A.FB_CREATE_TIME AS ${_iq_}createTime${_iq_}
    FROM DATAGEAR_FOO_BAR A
  </sql>

  <sql id="queryCondition">
    1 = 1
    <if test="queryKeyword != null">
    AND ${_iq_}name${_iq_} LIKE #{queryKeyword}
    </if>
  </sql>

  <select id="getById" resultType="org.datagear.management.domain.FooBar">
    SELECT T.* FROM (<include refid="queryView" />) T WHERE T.${_iq_}id${_iq_} = #{id}
  </select>

  <select id="query" resultType="org.datagear.management.domain.FooBar">
    SELECT T.* FROM (<include refid="queryView" />) T
    WHERE <include refid="queryCondition" />
    <include refid="common.queryOrder" />
  </select>

  <select id="pagingQueryCount" resultType="int">
    SELECT COUNT(*) FROM (<include refid="queryView" />) T WHERE <include refid="queryCondition" />
  </select>

  <select id="pagingQuery" resultType="org.datagear.management.domain.FooBar">
    <include refid="common.pagingQueryHead" />
    SELECT T.* FROM (<include refid="queryView" />) T
    WHERE <include refid="queryCondition" />
    <include refid="common.queryOrder" />
    <include refid="common.pagingQueryFoot" />
  </select>

</mapper>
```

> 需要数据权限时，`queryView` 中 LEFT JOIN `DATAGEAR_AUTHORIZATION` 并引入
> `commonDataPermissionSqls.xml` 的权限片段（参考 `AnalysisProjectMapper.xml`）。

### 第 5 步：Controller（`datagear-web/controller/FooBarApiController.java`）

```java
@Controller

    @Autowired private FooBarService fooBarService;
```

### 第 7 步：前端 API（`src/api/fooBar.ts`）

```ts
import request, { unwrap } from './request'
import type { OperationMessage, PagingData, PagingQuery } from '@/types'

export interface FooBar { id: string; name: string; value?: string; enabled: boolean }

export async function fooBarPagingQueryData(query: PagingQuery): Promise<PagingData<FooBar>> {
  const res = await request.post<OperationMessage<PagingData<FooBar>>>('/api/fooBar/pagingQueryData', query)
  return unwrap(res)
}
export async function getFooBar(id: string): Promise<FooBar> {
  return unwrap((await request.get<OperationMessage<FooBar>>(`/api/fooBar/get/${id}`)))!
}
export async function saveFooBar(entity: FooBar): Promise<FooBar> {
  return unwrap((await request.post<OperationMessage<FooBar>>('/api/fooBar/save', entity)))!
}
export async function deleteFooBars(ids: string[]): Promise<void> {
  await request.post<OperationMessage>('/api/fooBar/delete', ids)
}
```

> 简单模块也可直接用 `moduleGet/moduleSave/moduleDelete('fooBar', ...)` + `createPagingLoader('fooBar')`。

## 五、关键约定速查表

| 关注点 | 约定 |
|---|---|
| 统一响应 | 一切 `/api/**` 返回 `OperationMessage<T>`，前端 `unwrap()` 解包 |
| 分页 | `POST /api/{module}/pagingQueryData`，`page` 从 1 起 |
| 新增/更新 | `POST /api/{module}/save`，`id` 为空 = 新增（后端生成 `IDUtil.randomIdOnTime20()`） |
| 删除 | `POST /api/{module}/delete`，body 为 `String[] ids`（或自定义 form） |
| 元数据 | `GET /api/{module}/meta` 返回列定义 + readonlyAction |
| SQL 命名空间 | Domain 类全限定名（如 `org.datagear.management.domain.FooBar`） |
| Mapper 必含 statement | `insert / update / deleteById / getById / query / pagingQuery / pagingQueryCount` |
| 表/列命名 | `DATAGEAR_*` 大写下划线；主键 `VARCHAR(50)` |
| 数据权限 | 有权限 → `AbstractDataPermissionApiController` + `AbstractMybatisDataPermissionEntityService` + `CreateUserEntity` |
| Service 注册 | `CoreConfigSupport` 手动 `@Bean` |
| 前端类型 | 后端契约在 `types/index.ts` + `api/*.ts` 中一一对应 TS interface |
