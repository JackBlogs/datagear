# 阶段六：构建集成与部署

> frontend-maven-plugin 已挂入 `datagear-web/pom.xml`（默认 `skipFrontend=true` 跳过）。

---

## 一、启用前端构建（`-DskipFrontend=false`）

```bash
# 完整打包（会触发 npm ci + npm run build，产物拷入静态资源）
mvn package -DskipFrontend=false
```

- 前端源码目录：`datagear-web-ui/`（Node v20.11.0，由插件自动安装）
- 构建产物：`datagear-web-ui/dist/`（Vite 产物）

## 二、SPA 产物放置与托管（三选一）

| 方案 | 说明 | 适用 |
|---|---|---|
| **A. Spring 托管** | `dist/*` 拷入 `static/`，`index.html` 作为默认页；改造 `MainController.main()` 返回静态 index | 单 war 部署，最简单 |
| **B. nginx 同域反代** | nginx 托管 `dist/`，`/api`、`/login` 等反代到后端 | 独立前端部署，推荐生产 |
| **C. CDN** | `dist/` 上 CDN，后端仅 API（阶段七可选） | 独立域名 |

> 阶段一 POC 用 Vite dev server（5173）代理到后端（50401）即为方案 B 的开发态。

## 三、双形态打包验证（M5）

```bash
# 1. 可执行 war（java -jar）
mvn package -DskipFrontend=false
java -jar datagear-webapp/target/datagear.jar

# 2. 外置 Tomcat
cp datagear-webapp/target/datagear.war $TOMCAT/webapps/
```

## 四、收敛前提（勿提前执行）

当前 SPA 仍通过 iframe 双轨依赖旧视图（设计器/sqlpad/数据交换）。满足以下条件后，再运行 `scripts/converge-phase6.sh --execute`：
1. 看板设计器属性面板已完全 SPA 化（脱离 iframe）；
2. SQL 工作台/数据交换已脱离 iframe；
3. 菜单级灰度切换完成，旧模板保留一个迭代无回归。
