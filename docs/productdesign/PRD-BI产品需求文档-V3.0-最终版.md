# 第一部分 产品概述

## 1.1 产品定位

DataGear 是一款**开源免费、轻量、可私有化的"语义层驱动"商业智能（BI）分析平台**：

> 以数据集语义层与指标中心为地基，向上支撑自由看板、自助分析与 AI 增强分析（ChatBI），向外以开放 API / 嵌入 SDK / MCP 供给数据与指标，覆盖「接入 → 存储 → 治理 → 建模 → 分析 → 展示 → 分享」完整数据链路，服务中文场景与信创环境。

产品在保持私有化单体部署、轻量开箱即用（Java 8+ 即可运行）的同时，补齐语义层、数据治理、统计报表、数据填报、告警订阅与开放集成能力。

## 1.2 产品背景与要解决的问题

| 痛点 | DataGear 的解法 |
| --- | --- |
| 数据分散在数据库、文件、接口、消息队列等，缺乏统一入口 | 统一数据源管理，支持 JDBC 数据库、Excel/CSV/JSON 文件、HTTP 接口、实时流等多类接入 |
| 指标口径不一、同名不同义 | 语义层与指标中心统一口径，一处定义多处消费（图表/报表/告警/问数/API） |
| 数据质量参差、缺乏治理 | 元数据管理、数据标准、数据质量、数据血缘、数据脱敏构成数据治理体系 |
| 传统 BI 笨重、部署复杂、成本高 | 单体轻量架构，私有化掌控数据；Docker 一键部署 |
| 图表类型有限、缺 GIS/三维/大屏能力 | 70+ 内置图表 + GIS 地图工具 + 三维立体图表 + 大数据可视化大屏 + 图表插件机制 |
| 分析深度不足，难以层层下钻 | 数据钻取、图表联动、跳转穿透、参数过滤构成自助交互分析体系 |
| 取数依赖技术人员，业务不会 SQL | 可视化查询构建器 + 智能问数（ChatBI），自然语言/拖拽双自助 |
| 报表能力弱、无法满足中国式复杂报表 | 分组报表、交叉表、电子表格、填报、定时订阅推送与多格式导出 |
| 权限与数据安全难保障 | 基于角色的功能权限 + 资源/行列级数据权限 + 数据源防护 + 加密与脱敏 |
| 数据难以对外交换与分享 | 数据导入导出、数据 API 服务、签名 Token 嵌入、看板/报表分享、订阅推送 |

## 1.3 目标用户与典型场景

| 角色 | 场景 |
| --- | --- |
| 数据分析师 | 连接数据源、建模、拖拽生成图表、搭建看板与报表、自助下钻分析 |
| 业务人员 | 查看门户首页、访问已分享看板/报表、通过交互表单/钻取/智能问数自取所需数据 |
| 数据工程师 | 配置数据接入、执行数据治理、维护元数据与指标口径、开发数据交换任务 |
| 开发人员 | 自定义图表插件、扩展数据源驱动、调用数据 API、签名嵌入、二次开发 |
| 系统/数据管理员 | 管理用户/角色/组织/数据权限、数据源防护、指标认证、系统配置 |
| 企业决策层 | 大屏驾驶舱、经营报表、指标看板的集中展示与主动推送 |

## 1.4 产品价值

- **安全稳定**：私有化部署、数年迭代、基于角色的权限、数据默认私有、加密脱敏。
- **口径统一**：语义层与指标中心保障"一个指标一个口径"，贯穿图表、报表、告警与 AI 问数。
- **功能丰富**：多源接入、六类数据集、70+ 图表、GIS/三维/大屏、报表、模板化看板。
- **智能易用**：可视化查询构建器、智能问数（ChatBI）、AI 解读与归因，业务零 SQL 自助。
- **治理可控**：元数据、数据标准、数据质量、数据血缘、指标认证一体的轻量数据治理。
- **易于扩展**：运行时数据源驱动、自定义图表插件、开放看板 API、数据 API、嵌入 SDK 与 MCP。
- **自由制作**：原生 HTML 模板、可视化/源码编辑、多端响应式、联动钻取。

## 1.5 战略支点与产品边界

**三个战略支点**：

1. **语义层优先**：指标中心是 ChatBI 准确率、告警、嵌入、治理的共同地基，作为最高优先级的全新建设模块。
2. **AI 可插拔而非重写内核**：对标 SQLBot，智能问数做成独立可插拔模块（复用现有数据集/权限体系），支持 DeepSeek/Qwen/OpenAI 兼容接口的自带模型（BYO-LLM）。
3. **开放与嵌入放大生态**：签名 Token 嵌入、数据 API、MCP Server 三层开放，让 DataGear 可被第三方系统与 AI Agent 消费。

**明确不做（边界）**：

- 不做独立重型 ETL/数据集成产品；只做数据集内轻量数据准备，重 ETL 交由上游（SeaTunnel/Flink CDC 等）。
- 不做 SaaS 多租户云平台；坚持私有化单体 + 可选外置库高可用。
- 不做自研 OLAP 引擎；以"直连实时 OLAP + 缓存加速"双轨应对实时化。
- 不做裸 text-to-SQL 问数；坚持"语义层 grounding + DSL 中间层"的确定性路线。

## 2.3 六大趋势判断（战略输入）

| # | 趋势 | 对 DataGear 的含义 |
| --- | --- | --- |
| T1 | **语义层/指标层是一切高级能力（ChatBI、告警、嵌入、治理）的地基**；AtScale 基准显示 LLM 无语义层 grounding 时错误率约 80% | 优先建设轻量指标中心，且指标定义要"可 API 消费、可导出"（headless 形态） |
| T2 | **AI 取数走"确定性中间层"**（Text2DSL/NL2Skill），大模型只做意图理解 | DataGear 自有数据集/数据标记模型天然适合做 DSL，避免裸 NL2SQL |
| T3 | **告警/订阅/嵌入是开源用户口碑最集中的"非炫技"能力**，成本低见效快 | 排在 AI 大叙事之前落地 |
| T4 | **Agentic BI**：从"对话取数"到"监控-归因-建议"的主动洞察与多智能体协同 | 中期演进方向，依赖 T1/T2 成熟 |
| T5 | **可组合/Headless BI 与 MCP**：BI 资产以 API/MCP 向外供给 | 开放 API 与 MCP Server 是生态卡位 |
| T6 | **信创与实时 OLAP 适配**决定国内政企准入 | 数据源方言矩阵与性能验证需专项投入 |

| 移动端 | 仅看板响应式 | 全新建设（降级为 H5 深化策略） |

## 3.3 差距分析结论

1. **DataGear 的强项在"自由看板 + 插件体系 + 轻量部署"，弱项在"语义层、自助分析、企业级治理、开放集成"**——与 Superset（SQL 深度强/业务自助弱）、Metabase（自助与嵌入强/治理弱）形成错位竞争空间。
2. **多数规划项属于"全新建设"而非"增强现有"**，二次开发必须按基建（调度/邮件/开放 API/权限扩展）→ 语义层 → AI/告警/嵌入的顺序推进，不能并行摊大饼。
3. **DataEase/SQLBot 已验证"简单好用 + 可插拔问数 + 增值包"路径**；DataGear 的差异化空间在「中文场景 + 轻量私有化 + 数据集语义层 + 可嵌入 + AI 可插拔」的组合。

## 5.5 数据处理与建模 【已实现数据集基础，自助准备为全新建设】

### 功能概述

将数据源、文件、HTTP 接口等抽象为统一「数据集」，并提供建模与自助数据准备能力，供图表/看板/报表/语义层消费。对标 Metabase 查询构建器与 Superset 虚拟数据集，**明确不做独立重型 ETL**。

### 数据集类型

| 类型 | 标识 | 说明 | 关键配置 |
| --- | --- | --- | --- |
| SQL 数据集 | `SQL` | 基于数据源执行 SQL 查询 | 数据源、SQL 语句、参数 |
| HTTP 数据集 | `HTTP` | 调用 HTTP 接口并解析响应 | URI、请求头、方法、请求体、响应 JSON 路径 |
| JSON 值数据集 | `JsonValue` | 直接粘贴 JSON 文本 | JSON 内容、数据 JSON 路径 |
| JSON 文件数据集 | `JsonFile` | 读取 JSON 文件 | 文件名、编码、数据 JSON 路径、文件源 |
| CSV 值数据集 | `CsvValue` | 直接粘贴 CSV 文本 | CSV 内容、表头行 |
| CSV 文件数据集 | `CsvFile` | 读取 CSV 文件 | 文件名、编码、表头行、文件源 |
| Excel 数据集 | `Excel` | 读取 Excel 文件 | 文件名、Sheet、表头行、行列表达式 |
| 目录文件数据集 | （文件目录） | 读取目录内多个文件 | 目录、文件名模式 |

### 数据集参数与参数化语法

- 参数类型：`string / boolean / integer / number / object`。
- 参数输入控件：`text / select / radio / checkbox / textarea / date / time / datetime`，`select` 等可携带 `inputPayload` 定义选项 JSON。
- **参数化语法（SQL/JSON/CSV 模板）**：基于 Freemarker，使用 `${参数名}` 引用参数；SQL 数据集额外提供 `${pc(参数名)}` 预编译函数，防止 SQL 注入。

| FR-MODEL-04 | 多维模型 | 维度/度量定义，支撑多维分析与下钻（由 5.3 语义层 FR-SEM-01 承接） |

### 自助数据准备（新增，对标 Metabase / Superset / Power Query 轻量子集）

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| FR-PREP-01 | 可视化查询构建器 | 不写 SQL：选表/字段 → 过滤 → 聚合分组 → 排序 → 生成数据集；可随时切换 SQL"逃生舱" |
| FR-PREP-02 | 组合数据集 | 落实 Roadmap 待定项：多数据集经 SQL 连接/选取生成新数据集（CombineDataSet）；支持跨数据源（经内置计算引擎落地） |
| FR-PREP-03 | 数据集内转换步骤 | 在数据集上叠加轻量步骤：过滤、派生列（表达式）、去重、排序、透视、行列转换；步骤可回溯可编辑 |

# 第七部分 关键业务流程

## 7.1 数据接入 → 治理 → 展示主流程

```
数据接入（数据库/文件/HTTP/实时流）
   → 数据存储（元数据入库 / 缓存 / 抽取物化）
   → 数据治理（元数据 / 标准 / 质量 / 脱敏）
   → 建立数据集（SQL/HTTP/CSV/Excel/JSON，定义字段与参数）
   → 语义层建模（维度/度量/指标/术语，认证发布）
   → 创建图表/报表（选插件，绑定数据集或引用指标，做数据标记）
   → 组装看板/大屏（HTML 模板 + 图表部件 + 联动/钻取）
   → 分享/嵌入（密码分享、签名 Token、iframe、数据 API）
   → 终端展示（多端响应式、实时刷新、下钻分析）
   → 主动触达（阈值告警 / 订阅推送 / 指标关注动态）
```

## 7.2 数据集查询流程（参数化）

```
看板/图表/报表请求 → 携带参数值（DataSetQuery）
   → 数据集模板解析（Freemarker，${param} / ${pc(param)}）
   → 连接数据源执行（SQL/HTTP/文件读取）
   → 结果结构化（字段映射、类型转换、附加数据）
   → 返回 DataSetResult → 图表/报表渲染
```

## 7.3 指标查询流程（语义层）

```
指标消费方（图表/报表/告警/问数/外部 API）→ 提交「指标 + 维度 + 筛选 + 时间窗」
   → 指标定义解析（口径、聚合、同环比计算）
   → 编译为参数化 SQL（复用 ${pc()} 预编译）
   → 行列级数据权限改写 + 动态脱敏
   → 执行并缓存（数据集级缓存策略）
   → 返回结构化结果 + 口径元信息（供透明化展示）
```

## 7.4 智能问数流程（ChatBI）

```
用户自然语言提问
   → 知识库检索（术语/同义词/业务规则/golden queries，RAG）
   → 大模型意图理解与拆解 → 生成中间 DSL（指标/维度/筛选/排序/时间窗）
   → 命中认证答案？→ 是：直接返回认证结果
   → 否：DSL 经指标查询流程确定性执行
   → 行列权限与脱敏校验
   → 返回「图表 + 数据 + 自然语言结论 + 取数逻辑说明」
   → 用户追问/澄清（多轮上下文）或一键转图表/看板继续分析
```

## 7.5 权限校验流程

```
请求 → 身份识别（会话 / API Key / 签名 Token / 匿名）
   → 功能权限（角色/菜单）
   → 数据权限（Authorization 表：资源 × 主体 × 权限值 + 行列级过滤）
   → 数据脱敏（敏感字段按角色脱敏）
   → 业务执行
```

| **P3** | 复杂报表与填报（FR-RPT / FR-FILL） | 高（国内刚需） | 15–25 人周 | 工程量最大；建议作为商业化增值包单独立项 |

**目标**：交付可插拔智能问数 V1 与自助分析主线，形成对外传播点。

| 工作包 | 内容 | 对应需求 | 验收标准 |

| 内容治理 | 版本历史/回滚、内容认证、标签、使用分析 | FR-COLLAB-01/02/03/05 | 看板可回滚到任意快照；认证内容搜索优先 |

### Phase 3：生态与纵深期（3 个月以上，按商业策略裁剪）

- **Agentic 演进**：指标监控→异常检测→归因→推送的主动洞察（对标观远洞察 Agent / Tableau Pulse）；MCP Server（FR-EMBED-04）；AI 报告（FR-AI-07）。
- **设计器纵深**：dashboardEditor.js 真拖拽改造（Roadmap 待定项）、大屏设计器、复杂报表与填报（建议作为**企业版增值包**立项，对标 DataEase X-Pack 模式：开源核心保持轻量，增值能力商业化）。
- **数据治理纵深**：数据质量（FR-GOV-08~10）、字段级血缘与影响分析（FR-GOV-11~13）、数据集市（FR-STORE-07~09）。
- **信创纵深**：全栈适配验证与性能报告（项目驱动）。
- **移动深化**：H5 门户 + 订阅推送 + 扫码/拍照填报（跟随填报模块）。

## 8.3 路径决策逻辑（为什么是这个顺序）

1. **调度/嵌入/Docker 先行**：成本最低、所有后续模块依赖调度，且嵌入与 Docker 立即改善开源用户获取与集成体验（对标 Metabase 的成功要素）。
2. **语义层先于 AI**：国内外调研一致结论——无语义层的 ChatBI 等于"演示玩具"（AtScale 基准：无 grounding 错误率约 80%）；指标中心同时反哺告警、开放 API、首页，一次投入四处受益。
3. **告警/订阅/API 紧跟语义层**：三者都消费指标模型，打包建设边际成本最低，且都是"可感知、可演示"的刚需能力。
4. **问数 V1 放在 Phase 2**：此时语义层、术语库、行列权限均已就位，问数可做到"可解释、可干预、可认证"，避免裸 NL2SQL 的信任崩塌。
5. **报表/填报压轴且商业化**：工程量最大（15–25 人周）且是国内公认付费点（DataEase 将填报放入收费 X-Pack），适合作为企业版锚点而非开源核心的早期负担。

# 第九部分 风险与决策点

| # | 风险/决策点 | 影响 | 建议 |
| --- | --- | --- | --- |
| R1 | 前端栈混杂（jQuery + Vue3 + PrimeVue + Freemarker） | 拖拽设计器/问数 UI 等重交互开发效率低 | 新模块一律 Vue3 组件化，老页面渐进迁移；不强推全量重构 |
| R2 | Java 8 / Spring Boot 2.7 技术债 | DuckDB、部分 LLM SDK 需要更高 JDK | 问数等可选模块可要求 Java 17+，核心保持 8；或启动 JDK 升级专项（需评估） |
| R3 | 跨源组合查询引擎选型（DuckDB vs Calcite） | 影响组合数据集与问数能力上限 | 概念验证后定：DuckDB 轻量但 JVM 集成经 JNI；Calcite 纯 Java 但更重 |
| R4 | ChatBI 准确率达不到验收线 | 传播点变槽点 | 坚持 DSL 路线 + golden queries + 认证答案三重兜底；未达标不发布 |
| R5 | 范围蔓延（规划项过多） | 交付失焦 | 以 8.1 优先级矩阵为准；报表/填报/大屏/移动端明确后置 |
| R6 | 开源与商业化的边界 | 社区信任与收入 | 参照 DataEase：核心（语义层/告警/嵌入/问数基础版）开源，填报/复杂报表/审计/信创认证做企业版 |

# 第十部分 术语表

| 术语 | 含义 |
| --- | --- |
| 数据源（DtbsSource/Schema） | 注册到系统的外部数据库连接信息 |
| 数据集（DataSet） | 图表/看板/报表消费的统一数据抽象 |
| 图表部件（ChartWidget） | 绑定数据集与插件后的具体图表实例 |
| 图表插件（ChartPlugin） | 定义图表渲染逻辑与数据标记的可插拔单元 |
| 数据标记（DataSign） | 数据集字段到图表语义（名称/数值/类别）的映射 |
| 看板（Dashboard） | 基于 HTML 模板的多图表展示容器 |
| 大屏（Big Screen） | 面向大屏展示的看板形态 |
| 数据权限（Authorization） | 资源 × 主体 × 权限值 的授权 |
| 数据源防护（Guard） | 阻止恶意数据源 URL/连接属性的规则 |
| 文件源（FileSource） | 数据集文件的存储目录 |
| 项目（AnalysisProject） | 数据集/图表/看板/报表的归组单元 |
| 元数据（Metadata） | 描述数据的数据，含技术元数据与业务元数据 |
| 数据血缘（Lineage） | 数据从源头到消费端的流转与依赖关系 |
| 指标（Metric） | 统一口径的业务度量；原子指标 = 度量+聚合，派生指标 = 四则运算/同环比/占比/累计 |
| 语义层（Semantic Layer） | 在数据集之上统一声明维度/度量/指标/术语的模型层，一处定义多处消费 |
| 指标中心（Metrics Hub） | 指标的定义、目录、认证、版本、血缘与统一消费的功能集合 |
| 业务术语库（Glossary） | 字段/指标的同义词、业务用语与规则说明，ChatBI 的 grounding 基础 |
| DSL（问数中间层） | 大模型意图到确定性查询之间的结构化指令（指标/维度/筛选/排序/时间窗） |
| golden queries | 金标准问答对，用于问数知识库召回与准确率评估 |
| 认证答案（Verified Answer） | 管理员认证的标准回答，用户提问命中时直接返回 |
| 数据脱敏（Masking） | 对敏感数据做变形处理以保护隐私 |
| 签名 Token 嵌入 | 第三方系统以共享密钥签发时效 JWT，免登嵌入看板/报表的方式 |
| MCP（Model Context Protocol） | 让外部 AI Agent 以标准协议消费 BI 资产（指标/数据集）的开放接口 |
| BYO-LLM | 自带大模型：用户配置自己的 OpenAI 兼容接口（DeepSeek/Qwen/GLM/私有模型） |
| 信创 | 信息技术应用创新：国产芯片/OS/数据库/中间件/浏览器的全栈适配要求 |
