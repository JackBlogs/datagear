### 1.2 统一响应信封 OperationMessage

所有端点（含内部演示端点）必须返回统一信封：

```json
{ "code": 0, "message": "success", "data": { } }
```

- 成功：`code = 0`，`message = "success"`，`data` 为业务负载（对象 / 数组 / 布尔）。
- 失败：`code ≠ 0`，`message` 为**可直接展示给用户的可读文案**，`data = null`；不得暴露堆栈与内部错误细节（SDS 安全设计 / NFR-SEC-04）。

**code 语义表（IX-BASE-00，前后端共同遵守）**

| code | 语义 | 典型触发（mock-api.js 实证） | 前端统一处理约定 |
| --- | --- | --- | --- |
| 0 | 成功 | 全部 `ok(data)` | 取 `data` 渲染；写操作给成功 Toast（3 秒） |
| 400 | 参数与校验错 | `POST /auth/login` 缺账号密码→`请输入账号与密码`；验证码错→`验证码错误，请重新输入`；`metric/save` 缺 name→`指标名称不能为空`；`dtbsSource/save`→`名称与连接地址不能为空`；`user/save`→`姓名与账号不能为空`；`ai/chat/ask` 空问题→`问题不能为空` | 表单场景将 `message` 定位到首个错误字段下方红字；非表单场景 err Toast |
| 401 | 未认证 / 凭证失效 | API Key 无效/过期/吊销；嵌入 Token 过期/签名错误（UC-003/006） | Web 端跳 `login.html`；嵌入端回调 `onTokenExpired` 请宿主重新签发 |
| 403 | 越权 / 白名单拒绝 | 无资源权限；嵌入域名不在白名单；IP 白名单外调用 | 只提示「您暂无权限，请联系管理员」，不暴露任何数据（PRD 5.4、UC-002） |
| 404 | 资源或接口不存在 | `GET /semantics/metric/detail/:id` 未命中→`指标不存在`；路由未注册→`接口不存在：METHOD path` | 详情类展示空态+返回入口；列表类展示错误块+重试 |
| 429 | 限流 | 数据 API 超 QPS/日配额（SDS 接口设计：429 + `Retry-After` 响应头） | Toast「调用超限，请稍后重试」，按 `Retry-After` 秒数禁用重试按钮 |
| 500 | 服务异常 | `failHook` 注入→`服务繁忙，请稍后重试（模拟 500）`；handler 抛错→`err(500, e.message)`；`dtbsSource/test` 连接超时→`连接超时（3 秒）：…` | 错误块「原因 + 建议 + 重试」三要素；不展示堆栈 |

### 1.4 鉴权三通道与前端的体现（SDS 安全设计）

| 通道 | 凭证携带方式 | 适用端 | 前端/调用方约定 | 401 表现 | 403 表现 |
| --- | --- | --- | --- | --- | --- |
| 会话 Cookie | 登录后 Set-Cookie 会话（`POST /auth/login` 返回 token，演示值 `mock-session-*`），后续请求同源携带 | Web 端全部内部端点 | 浏览器自动携带；跨域需 `credentials: 'include'` | 跳 `login.html` 重新登录 | Toast「您暂无权限」 |
| API Key | 请求头 `X-API-Key: dgak_…` | 数据 API（`/api/v1/{path}`）与 MCP | 调用方保管完整 Key（仅创建时展示一次）；Key 过期/吊销/IP 白名单外分别返回 401/401/403 | 返回 401 + 可读 message；调用监控记录 | 403 +「该 IP/域名未授权」 |
| 嵌入签名 JWT | URL query `?token=<jwt>`（HS256 共享密钥签发，payload 含用户/组织/角色/资源/参数/过期，建议 ≤5 分钟） | 嵌入端（iframe / Embed JS SDK） | 嵌入页所有交互请求携带同一 token；过期由 SDK `onTokenExpired` 回调宿主后端重新签发 | 401 → SDK 展示「嵌入认证失败，请联系管理员」 | 403 →「该域名未授权嵌入」/「您暂无权限查看该看板」 |

## 5 前后端联调与替换说明

### 5.1 mock → 真实后端切换步骤

1. **替换入口**：仅重写 `DG.api.request(method, path, {query, body})` 为真实 `fetch` 实现；`get/post/put/del` 包装签名保持不变，页面脚本零改动。
2. **信封保持**：后端必须返回 `{code, message, data}`；前端统一在 `request` 层判断 `code===0`，非 0 走 1.2 的错误处理约定（不得各页面自行发明错误格式）。
3. **路径与参数**：URL path、query 键、body 字段名与本规范第 4 章一致；`{id}` 路径参数 URL 编码（mock 用 `decodeURIComponent` 解码）。
4. **延迟与三态演示**：mock 延迟 120~600ms（`DG.api.setLatency(a,b)` 可调）；联调/验收时可用 `failHook` 思路在后端注错，验证各列表三态与重试。
5. **静态资源路径约定**：原型为相对路径（`assets/css/theme.css`、`assets/js/*`）；生产嵌部署到子路径时需统一 base，避免 shell 注入与跳转 404；页面间跳转（`location.href='*.html'`）生产替换为路由地址时须保持第 2/3 章「跳转带参」约定（如 `chatbi.html?q=` → `/chatbi?q=`）。

### 5.2 跨域与凭证约定

- **会话 Cookie**：跨域部署时 `fetch` 必须 `credentials:'include'`，服务端设置 `SameSite=Lax`（嵌入场景第三方站点需 `SameSite=None; Secure` 并走签名 Token 通道而非会话）；CORS 白名单显式枚举，禁止 `*` 携带凭证。
- **API Key**：调用方请求头 `X-API-Key: dgak_…`；服务端校验顺序：Key 有效（401）→ IP 白名单（403）→ 限流（429+Retry-After）→ 参数校验（400）→ 权限管道（行/列/脱敏）→ 执行（UC-006）。
- **嵌入 JWT**：第三方后端用共享密钥 HS256 签发，payload 含 `uid/org/roles/resource/params/exp`（`exp` 建议 ≤5 分钟）；前端以 query `?token=` 或 SDK `DataGearEmbed.render(dom,{resource,token,theme,params})` 注入；校验失败分别返回 401（签名/过期）/403（白名单/资源越权），SDK 回调 `onTokenExpired` 触发重新签发；密钥吊销后全部已签发 Token 立即失效。
- **写操作头**：`Content-Type: application/json`；删除类用 `DELETE /x/{id}` 或 `POST /x/delete`（见第 4 章具体端点）。
