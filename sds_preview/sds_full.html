引言

编写目的

本文档是 DataGear 商业智能分析平台的软件开发说明书（SDS），与《PRD-BI产品需求文档-V4.1-优化版》配套：PRD 定义「做什么、为什么、先做什么」，SDS 定义「怎么做」。本文档面向架构、开发、测试与二次开发人员，给出可落地的系统设计：分层架构、表级数据模型、17 个功能模块的组件/类/流程/接口设计、安全与性能设计、AI 质量设计与迭代实现设计。

设计约束与口径一律以 PRD V4.1 为准：范围不做重型 ETL、不做 SaaS 多租户、不做自研 OLAP 引擎、不做裸 text-to-SQL；性能口径统一为 P95≤3 秒；并发口径为 300 并发用户/50 并发分析任务（估算，待压测验证）；问数验收为标准问题集≥200 题盲测准确率≥85%、<80% 降级为检索式问答。

项目背景

DataGear 6.0.0 已具备数据接入、六类数据集、70+ 图表、自由看板、资源级授权等能力（详见 PRD 现状盘点）。本期建设的核心是：语义层与指标中心（最高优先级全新建设）、可插拔 AI 增强分析、告警与订阅推送、开放 API 与签名嵌入、行/列级数据权限、Docker 交付与综合首页。设计须遵循 PRD 的路径决策：调度/Docker 先行、语义层先于 AI、内核工程（行列权限 SQL 改写、指标 SQL 编译）先行 Spike 验证后再锁工期。

总体设计

设计目标与约束

类别

内容

设计目标

以最小侵入方式在 6.0.0 内核之上扩展：新增子模块独立装配、可整体移除；核心零 LLM 依赖；「一处定义、多处消费」的语义层贯穿图表/报表/告警/问数/API

技术约束

核心保持 Java 8 + Spring Boot 2.7（AI 等可选模块可要求 Java 17+）；前端新模块一律 Vue3 组件化，旧 jQuery 页面渐进迁移不强推重构；存储保持「内置 Derby 开箱即用 + 外置 MySQL 生产推荐」

部署约束

单 war 内嵌 Tomcat / Docker 单容器底线不被新模块破坏；配置外置（application.properties + 环境变量）

范围约束

四个不做：不做独立重型 ETL、不做 SaaS 多租户、不做自研 OLAP 引擎、不做裸 text-to-SQL

质量约束

性能 P95≤3s 口径；问数 ≥200 题盲测 ≥85% 验收门槛与 <80% 降级退路；度量系统（埋点）先于被度量对象交付

关键设计决策

编号

决策

理由（源自 PRD 路径决策逻辑）

影响

SD-01

四个不做：不做重型 ETL / SaaS 多租户 / 自研 OLAP / 裸 text-to-SQL

边界克制，控制范围蔓延（PRD 风险 R5）

重 ETL 交由上游；实时化走「直连 OLAP+缓存」双轨

SD-02

语义层先于 AI

无语义层 grounding 的 ChatBI 错误率约 80%（AtScale 基准）；指标中心反哺告警、API、首页，一次投入四处受益

datagear-semantics 为最高优先级新模块

SD-03

AI 可插拔而非重写内核

对标 SQLBot；BYO-LLM 自带模型

datagear-ai 独立装配，未配置模型时自动隐藏

SD-04

核心零 LLM 依赖

规避 AI 技术快速迭代风险（PRD 风险 R10）

核心包无 LLM SDK 依赖，可保持 Java 8

SD-05

调度/Docker 先行，嵌入随 Phase 1

调度是所有定时类能力的基建；Docker 立即降低部署门槛；嵌入自 MVP 移至 Phase 1（V4.1 调整）

Phase 0 工作包编排

SD-06

行列权限与指标编译视为内核工程，先行 Spike

估算偏差风险高（PRD 评审结论）

Phase 0 安排两个各 1–2 周 POC，通过后才锁工期

SD-07

度量系统先于被度量对象交付

MVP 成功度量依赖使用分析

Phase 0 交付最小埋点子集（匿名、可关闭）

SD-08

报表/填报/大屏作为企业版增值包

工程量最大且是国内公认付费点（DataEase X-Pack 先例）

P3 立项，开源核心不承担早期负担

安全设计

认证与授权模型

三认证通道（会话/API Key/签名 JWT）统一汇入 Spring Security 过滤链；授权模型四层：功能权限（角色/菜单）→ 资源级数据权限（Authorization 四档）→ 行级权限 → 列级权限+动态脱敏。数据默认私有（仅创建者可见，授权共享）。关键约束：所有数据访问（查询/导出/API/问数/嵌入）均经过完整权限管道，无绕过路径（PRD UC-005 验收口径）。

行列级权限 SQL 解析改写方案

采用「SQL 解析器 + AST 改写」方案（详见「系统管理」★模块设计）：解析器选型在 Apache Calcite 与 JSqlParser 之间经 Phase 0 Spike① POC 验证后锁定，POC 结论（覆盖率/性能/方言兼容性）回填本节。安全兜底：解析或改写失败一律拒绝查询并记错误日志，不返回任何数据。权限规则读取走缓存、变更即失效（实时生效≤10 秒）。

签名嵌入 Token 机制

详见「数据交换、嵌入与开放 API」★模块设计。要点：HS256 共享密钥、Token 建议≤5 分钟时效、白名单域名、密钥可吊销即时生效、全程审计日志。

审计日志设计

DG_AUDIT_LOG 记录全部关键操作（登录失败/权限变更/数据导出/分享/API 调用/嵌入调用/回滚）；审计列表支持按时间/用户/操作类型筛选，关键操作高亮，可导出；日志中敏感信息脱敏（NFR-SEC-04）。

信创合规要点

达梦/人大金仓双库适配+冒烟验证清单（Phase 2 并行专项）作为政企交付材料；国密算法适配（传输/存储）为可选加分项（FR-XC-03）；数据安全合规（数据安全法/个保法）依赖行列权限+动态脱敏+审计日志+外发审批完整体系（PRD 风险 R11 对策）。
