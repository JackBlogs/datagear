步骤

处理

说明

1

接收 MetricQuery（指标+维度+筛选+排序+时间窗）

来自图表/指标卡/告警/问数/开放 API 的统一查询对象

2

指标定义解析

原子指标取度量+聚合；派生指标递归展开公式引用的子指标

3

维度展开

层级维度按当前层级取字段；时间窗转为时间字段过滤

4

SQL 编译

生成 SELECT 维度字段+聚合度量 … GROUP BY；复用数据集 Freemarker 参数化与 ${pc()} 预编译机制，防注入

5

行列权限改写

调用权限改写管道（见「系统管理」★），追加行过滤、裁剪列

6

动态脱敏

按角色应用脱敏规则

7

执行与缓存

检查数据集级缓存策略，命中直接返回；未命中执行并写缓存

8

返回结果+口径元信息

数据 + 指标口径说明 + 耗时 + 缓存命中标记（供透明化展示）

同环比计算：派生指标标记同环比属性时，编译为双时间窗子查询再 JOIN/UNION 计算，或下推 OLAP 引擎窗口函数（按方言能力适配）。

POC 验证方案要点（Phase 0 技术 Spike②，1–2 周）

验证项

通过标准

典型指标编译正确性

原子/派生/同环比各≥5 个典型指标编译结果与手写 SQL 结果一致

参数化兼容

与既有 Freemarker 数据集模板、${pc()} 预编译机制无冲突

性能基线

百万级数据经 OLAP 引擎 P95≤3s 可达（配合方言下推）

结论产出

POC 报告归档；通过后才锁定指标中心内核工期（PRD 要求：估算基于 POC 结论，偏差风险高）

接口设计

内部接口：`MetricQueryEngine.execute(MetricQuery)` 供图表/告警/问数/API 复用；`MetricManager` 提供 CRUD 与认证操作。REST 接口见「接口设计」章。

异常与降级

指标查询超时→返回加载超时与「缩小时间范围」建议；派生公式引用不存在指标→保存时阻断；数据集变更导致字段缺失→指标标记「失效」并在目录提示；编译失败→记录错误日志并返回可读原因，不暴露堆栈。

依赖

依赖数据集（org.datagear.analysis）与权限体系；被展示层、告警、ChatBI、开放 API 依赖（是一切高级能力地基）。
